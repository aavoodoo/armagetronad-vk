BUGS

BUG 3 — Multi-viewport first-round flickering
  Status: Closed

BUG 5/19 — Player names drift away from cycles
  Status: Fixed
  Player names and cockpit text rendered beside cycles sometimes appear far from
  the actual cycle position or invisible. Likely a matrix stack issue — the name
  rendering reads a stale or wrong modelview transform. Similar root cause to the
  original BUG 7 flash (matrix stack contamination between cycle renders).
  On macOS multi-viewport with 3-attachment FBOs (emissive variant), fonts can
  become completely invisible. With 2-attachment FBOs fonts work but z-fighting
  returns. iPad works with 2-attachment FBOs.

BUG 11 — Cockpit widget positioning on widescreen
  Status: Matches original GL behavior (by design)
  The square viewport + Readjust(4/3 / aspect) system is identical to the original
  OpenGL code. On 16:9, top widgets (clock, FPS) may be off-screen — this is the
  same as the original game. Cockpit XMLs designed for 4:3 don't fully fill 16:9.
  Future: Add top-anchored widget positioning mode so cockpit XMLs can adapt to
  any aspect ratio.

BUG 20 — Shadow map resource double-destroy on shutdown (low priority)
  Status: Open (macOS, may be platform-specific)
  On shutdown, shadow map VkImageView and VkSampler handles trigger "Invalid Object"
  validation errors. The textures_ map entries are erased before destruction, but
  the DestroyShadowMaps cleanup still references stale handles. Cosmetic only —
  no runtime impact, no crashes. Proper fix: track ownership more precisely or
  null handles after textures_ erase.

BUG 14 — About screen always blank (low priority)
  Status: Workaround applied
  uMenu::Message rendering is broken in the Vulkan port. The original GL code
  used immediate-mode draws (BeginQuads/Vertex/RenderEnd) between ClearGL/SwapGL.
  The Vulkan port wrapped this in rRenderFrame but the lazy BeginFrame never
  triggers inside the callback — geometry is submitted to the HUD queue but
  drawn into no active render pass. Matching the original ClearGL/SwapGL flow
  still fails (SwapGL was missing from the sr_glOut branch, causing freeze;
  after fixing, text still blank for unknown reason).
  Workaround: About screen uses a regular uMenu (same render path as all
  working menus) with version info in the title. uMenu::Message remains broken
  for other callers (fullscreen server messages, etc.).

BUG 15 — Flashing when switching moviepacks (medium)
  Status: Fixed
  Root cause: LeftRightRelease activated moviepacks on every scroll, triggering
  full resource reload (shader recompile, texture unload, settings change) 2x per
  scroll (deactivate + activate). Pipeline destruction + rebuild caused visual flash.
  Fix (3 parts):
    1. Browse/activate separation: LeftRight/LeftRightRelease only browse (preview
       images loaded lazily from ZIP). Enter activates (full resource reload).
    2. Debounced shader reload: ReloadShaders always defers to next BeginFrame via
       pendingShaderReload_ flag. DoReloadShaders runs once at frame boundary.
    3. Mid-game switching enabled: removed sg_GameRunning() guard. sr_vkWaitIdle()
       ends current frame + waits for GPU idle before texture/model unloading.

BUG 16 — SDF/MSDF/MTSDF font glyph rendering regression
  Status: Fixed (3 root causes)
  1. Single-channel texture mapping: SDF data stored as (255,255,255,A) but shader
     reads .r. Fixed: store as (V,V,V,V) in all channels — works for both legacy
     (reads .a for alpha blend) and SDF (reads .a for distance field).
  2. Atlas grow UV mismatch: when atlas doubles in size, cached glyph UVs were
     computed with old dimensions, pointing 2x too far. Fixed: rescale all cached
     UVs after grow (packOrGrow helper, single implementation for SDF/MSDF/MTSDF).
  3. Sampler maxLod: font atlas uses GL_LINEAR (no mipmap) but Vulkan sampler had
     maxLod=9, sampling stale higher mip levels. Fixed: clamp maxLod to 0.25 when
     usesMipmapFilter=false.

BUG 17 — Cockpit not rotated in multi-viewport split-screen
  Status: Partially fixed
  Per-player cockpit and VIEWPORT_TOP (clock, FPS) now render inside the viewport
  FBO, so they rotate with the 3D scene in the composite pass.
  Fix: sr_RenderViewportCockpit() called from RenderAllViewports before
  sr_EndViewportFBO(). display_cockpit_lucifer skips per-player cockpits in
  multi-viewport mode.
  Remaining: global overlays not yet rendered per-viewport:
    - Chat messages, console input
    - Winning/score messages
    - In-game menu
    - Global touch buttons (L1/R1/L2/R2)
  These render at various points in the frame lifecycle outside the viewport loop
  and would need to be restructured to render into each FBO.

BUG 18 — Keyboard tutorial shown on touch-only devices
  Status: Open
  The keyboard control tutorial messages reference physical keys that don't exist
  on touch devices. Should be disabled when no physical keyboard is available
  (iOS/Android touch mode).

  Cause: ReloadShaders deferred to next BeginFrame interacts with the menu's
  render frame lifecycle.

REVERSE-Z MIGRATION (2026-05-02)
--------------------------------

Status: Done for the main scene path; one residual asymmetry left for follow-up.

Why: forward-Z + tiny zNear (0.0001) + float32 wasted depth precision near the
far plane. All scattered depth workarounds (zNear *= .3f shrink, macOS force-PP
passthrough, depth-sampling kludge in passthrough.frag, periodic depth-precision
logging in eCamera) were symptoms. Reverse-Z gives uniform float precision
across the whole range and obviates those workarounds.

Changes:
  - rVulkanRender.cpp: new VkClipReverseZ() static, baked into Frustum/Ortho/
    Perspective. Composite of GL→VK depth remap + reverse-Z (no Y-flip — see
    below). Y-flip stays per-vertex in uber.vert / uber_instanced.vert.
  - rVulkanPipeline.cpp: depthCompareOp = GREATER_OR_EQUAL for all main scene
    pipelines. Shadow pipeline kept on LESS_OR_EQUAL (independent forward-Z).
  - All main-scene depth clear values flipped 1.0f → 0.0f (rVulkanRender.cpp
    BeginFrame / Clear / BeginViewportFBO / EndViewportFBO,
    rVulkanPostProcess.cpp). Shadow clears stay at 1.0f.
  - rVulkanRender.cpp::PolygonOffset negates inputs so existing GL-style
    callers (sr_DepthOffset(-2,-5)) still pull decals toward the camera.
  - shaders/uber.vert and uber_instanced.vert: removed per-vertex
    (z+w)*0.5 GL→VK depth remap (now in the matrix). Y-flip kept in shader
    because the HUD phase (rRenderQueue.cpp:294-299 SetupPhase) sets
    projection to identity, bypassing Frustum/Ortho/Perspective; baking
    the Y-flip in the matrix would leave HUD upside-down.
  - shaders/postprocess/passthrough/passthrough.frag: removed depth-sampling
    kludge that existed only to defeat MoltenVK's dead-code elimination
    under fragile float precision.
  - eCamera.cpp: zNear floor 0.0001 → 0.05 (precision pressure removed,
    floor only needs to clear the player's cycle model). Periodic
    [DEPTH] zNear/zFar/ratio logging removed (its math assumed forward-Z
    and would print misleading values under reverse-Z).
  - shaders/uber.frag: DEBUG_DEPTH_VIZ block updated to compute linearized
    view-space distance (forward-Z visual convention: near = black, far =
    white) so the visualization is interpretable when enabled.

Verification: client + server rebuilt clean for Linux (build_client +
build_server reconfigured because the pre-existing Makefiles had macOS
homebrew paths and protoc-26 .pb.h files that referenced runtime_version.h
absent from system protobuf 3.21). Multiple frames captured via
baseline.aarec playback and inspected with depthviz on/off, with and
without customBloom moviepack. Geometry orientation correct, depth
ordering correct, no visible regression vs. forward-Z without PP.

Offscreen RP cross-frame sync (FIXED 2026-05-02):
  The offscreen render pass previously had only an OUTGOING subpass
  dependency, while the swapchain render pass (rVulkanFramebuffer.cpp:
  138-163) had both incoming and outgoing. With the offscreen depth/
  color/emissive images being single shared images (not per-frame),
  this allowed frame N's depth-clear to race frame N-1's PP-composite
  shader read of the same depth image — pre-existing but a likely
  source of residual z-fighting / occasional all-black frames when a
  moviepack with PP was active.

  Fix: added an EXTERNAL→subpass-0 incoming dependency at
  rVulkanPostProcess.cpp:663-680. srcStageMask=FRAGMENT_SHADER,
  srcAccessMask=SHADER_READ → dstStageMask=COLOR_ATTACHMENT_OUTPUT |
  EARLY_FRAGMENT_TESTS, dstAccessMask=COLOR_ATTACHMENT_WRITE |
  DEPTH_STENCIL_ATTACHMENT_WRITE. Both binaries rebuilt clean and
  smoke-tested with customBloom moviepack via baseline.aarec playback.

  If artifacts still recur, option 2 (make offscreen images per-frame
  with MAX_FRAMES_IN_FLIGHT×3 allocations) fully decouples frames and
  pairs with the dependency above.

Transparent back-to-front sort (DONE 2026-05-02):
  rRenderQueue::ExecutePhase now distance-sorts buckets in the
  Transparent phase only (other phases keep state-only sort for
  binding batching). Effects is intentionally NOT sorted — it uses
  additive blend, which is commutative, and depth-test alone is
  enough to occlude particles behind walls. Opaque phases rely on
  depth-test for visibility resolution.

  Camera world position is fetched via the new sr_GetCameraWorldPos /
  sr_vkGetCameraWorldPos pair (added alongside the existing setter);
  centroid-vs-camera squared distance is computed once per bucket per
  execute via a decorate-sort-undecorate pattern. Far buckets render
  first so closer overlays composite on top — fixes alpha-blend
  wrongness on overlapping zones. Cost: O(N) pass over Transparent-
  phase vertices + O(B log B) sort, sub-millisecond at typical counts.

DepthFunc API removed (DONE 2026-05-02):
  vkRenderer::DepthFunc was a silent no-op while the pipeline cache
  hardcoded the compare op — a footgun for any caller expecting GL-
  style behaviour. Deleted: rRender.h::DepthFunc virtual + both
  RenderDepthFunc inline helpers (int and rCompareFunc overloads),
  vkRenderer::DepthFunc declaration / implementation / depthFunc_
  member / initializer, and the single caller in rScreen.cpp:1438
  (it passed LEqual which under reverse-Z would be wrong anyway —
  the active path is GREATER_OR_EQUAL fixed in the pipeline cache).
  The depthFunc accessor on rRenderState (utilities/rRenderState.cpp)
  is internal dead code; left in place as no callers reference it.

Front-to-back opaque sort (DONE 2026-05-02):
  rRenderQueue::ExecutePhase now distance-sorts OpaqueStatic and
  OpaqueDynamic phases front-to-back (closest first) so the GPU's
  early-Z rejects fragments of farther geometry without shading
  them. Reuses the centroid + camera-distance machinery from the
  Transparent sort. Effects keeps state-sort (additive blend +
  depth-test makes order irrelevant); HUD/Sky keep state-sort (no
  depth test). Cost is a small CPU sort; benefit scales with
  fragment-shader cost and overdraw — modest for Tron's simple
  shaders but free in dense scenes.

Depth pre-pass (NOT IMPLEMENTED, analysis sufficient for now):
  A "fully correct" depth pre-pass on this codebase requires a
  depth-only pipeline variant (no fragment shader, or empty FS, or
  colorWriteMask=0 + depthWrite-only) plus running OpaqueStatic +
  OpaqueDynamic phases twice (prepass + color). Maintenance budget:
  ~1-2 hours of careful work across rVulkanPipeline.cpp,
  rVulkanRender.cpp, rRenderQueue.cpp.

  Expected benefit on this game: negligible. Reasons:
    - Fragment shaders are simple (unlit floor/walls, simple lit
      cycles, hooks for emissive). Not the kind of expensive PBR
      where prepass shines.
    - Profiling shows the game is not GPU-bound — frame rate is
      capped by the platform display path, not by fragment work.
    - Overdraw in typical Tron view is modest (camera looks down at
      floor + walls, walls are mostly disjoint).
    - The colorWriteMask=0 shortcut would still run the fragment
      shader during prepass, doubling its CPU cost on the GPU command
      stream for zero shading saved.

  Recommended trigger to revisit: if a future moviepack adds an
  expensive PBR-style fragment hook AND profiling shows fragment work
  dominates frame time in dense gameplay scenes, then implement.
  Until then, the existing front-to-back opaque sort already gives
  the GPU's hardware early-Z most of the benefit a CPU-driven prepass
  would.

  pack that replaces the per-fragment Blinn-Phong + half-Lambert + specular
  + shadow on cycle bodies with clamped-Lambert diffuse only, recreating
  the original game's flat-lit look. Implementation is a single
  uber_hooks.glsl with a custom hookCycle; all other components and the
  vertex shader stay default. POST_PROCESS_ENABLED 0.

  To support minimal moviepacks like this one without forcing them to
  bundle the full texture set, added a sg_MoviepackHasFile(relPath) helper
  in gMoviepack and rewired the texture-selection sites:
    - gFloor.cpp::SelectFloorTexture / SelectFloorTextureA / SelectFloorTextureB
      use the moviepack's floor*.png only when the pack ships them; fall
      back to textures/floor*.png otherwise.
    - gWall.cpp's rim-wall bucket logic and stretch parameters gate on
      sg_MoviepackHasFile("rim_wall_a.png"). When the moviepack lacks the
      rim_wall_a/b/c/d set, geometry routes to the default-texture bucket
      (4) and uses the system rim wall texture.
    - eAdvWall.cpp passes the default rim wall texture into FlushBatch
      whenever the moviepack doesn't ship its own rim walls.
    - gCycle.cpp::dir_eWall_select() (the cycle-trail / "directional"
      wall texture) gates on sg_MoviepackHasFile("dir_wall.png") and
      falls back to textures/dir_wall.png. Sky textures already had a
      hand-rolled fallback (eDisplay.cpp se_Sky / se_UpperSky) — left
      as is since they predate this helper and use the same idiom.

  Net result: customGouraud is ~16 KB (settings.cfg + hooks + .spv) and
  renders the entire scene correctly — cycles with diffuse-only lighting
  (no specular highlights), default textured floor + rim walls + dir
  walls. Verified via baseline.aarec playback at frames 350/700/900.
